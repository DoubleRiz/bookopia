# Revue des RLS et contrôle des dépôts : plan d'implémentation

> **Pour les agents :** sous-skill requis : superpowers:subagent-driven-development (recommandé) ou superpowers:executing-plans, tâche par tâche. Les étapes se cochent (`- [ ]`).

**But :** prouver par des tests que fonctions et tables restent fermées, refuser un dépôt sous un livre qui n'est pas le sien, et plafonner un livre à 100 photos.

**Architecture :** deux migrations (dépôt, plafond), deux fichiers pgTAP (droits des fonctions, plafond), des tests ajoutés à `autorisations_test.sql`. Dans le front, l'import réserve une place avant chaque préparation et traduit le refus de la base.

**Pile :** PostgreSQL et Supabase (RLS, Storage, pgTAP), TypeScript, Vitest.

**Spec :** [`docs/superpowers/specs/2026-11-20-revue-rls-design.md`](../specs/2026-11-20-revue-rls-design.md)

## Contraintes globales

- Tout en français : identifiants, commentaires, messages, commits (impératif, sans point final).
- Chaque fonction SQL est commentée en français, `search_path = ''`, exécution révoquée à `public` et `anon` (et à `authenticated` si elle n'est pas appelable par `rpc`).
- Plafond : **100** photos par livre. Code d'erreur `plafond`, détail `Un livre compte au plus 100 photos`.
- Libellé E5 : « Livre complet (100 photos) ».
- Aucune dépendance nouvelle.
- Avant chaque commit : `npm run lint && npm run typecheck && npm test`, et `supabase test db` pour les tâches qui touchent la base.

## Points de vigilance

1. Deux onglets importent dans le même livre à 99 photos : un seul passe, l'autre reçoit `plafond` et ses fichiers sont supprimés. Couvert par le verrou (tâche 3) et par le test d'`envoyer` (tâche 4).
2. Reprise d'un import dans un livre déjà plein : aucun fichier n'est préparé ni déposé. Test dans la tâche 4.
3. Dossier d'un uuid en majuscules : PostgreSQL l'accepte, la règle aussi (expression régulière insensible à la casse). Test dans la tâche 2.
4. Le bucket `exports` suit le même chemin `{utilisateur}/{livre}/…` : le dépôt d'un PDF sous son livre passe toujours. Test dans la tâche 2.
5. Supprimer une photo libère une place. Test dans la tâche 3.

### Tâche 1 : test des droits d'exécution (BK-118)

**Fichiers :**

**Interfaces :** aucune. Le fichier ne dépend d'aucune autre tâche ; la tâche 3 ajoute une fonction trigger qui doit y rester invisible (exécution révoquée à tous).

- [ ] **Étape 1 : écrire le test**, sur le modèle d'en-tête des autres fichiers (`begin`, `create extension if not exists pgtap with schema extensions`, `plan(3)`, `finish()`, `rollback`). Les fonctions retenues sont celles de `pg_proc` du schéma `public` qui n'appartiennent pas à une extension (`not exists` dans `pg_depend` avec `deptype = 'e'`).

```sql
select is_empty(
  $$ select p.oid::regprocedure::text from … where has_function_privilege('anon', p.oid, 'execute') $$,
  'Aucune fonction de public n''est exécutable par anon'
);

select set_eq(
  $$ select p.oid::regprocedure::text from … where has_function_privilege('authenticated', p.oid, 'execute') $$,
  array[
    'est_mon_projet(uuid)',
    'creer_projet(text,uuid,uuid[])',
    'inserer_double_page(uuid,uuid,integer)',
    'deplacer_double_page(uuid,integer)',
    'supprimer_double_page(uuid)',
    'dupliquer_double_page(uuid)',
    'remplir_emplacements(uuid)',
    'composer_livre(uuid,jsonb)',
    'changer_gabarit(uuid,uuid)',
    'changer_theme(uuid,uuid)',
    'segments_texte_valides(jsonb)',
    'contenu_texte_valide(jsonb)',
    'placer_cadre_texte(uuid,numeric,numeric,numeric,numeric)'
  ],
  'authenticated n''exécute que la liste blanche'
);

select is_empty(
  $$ select … where p.prosecdef and not exists (
       select 1 from unnest(coalesce(p.proconfig, '{}')) c where c like 'search_path=%') $$,
  'Chaque fonction security definer fixe son search_path'
);
```

Le texte de `regprocedure` est sans le préfixe `public.` quand `public` est dans le `search_path` de la session de test : vérifier la forme réelle au premier lancement et ajuster la liste, pas la requête.

### Tâche 3 : plafond de 100 photos en base (BK-120)

**Fichiers :**
- Créer : `supabase/tests/plafond_photos_test.sql`
- Créer : `supabase/migrations/20261120100100_plafond_photos.sql`

**Interfaces :**
- Consomme : `public.verrouiller_projet(uuid) returns void` (lève `introuvable` si le livre n'est pas au Créateur).
- Produit : erreur `P0001`, message `plafond`, détail `Un livre compte au plus 100 photos`, sur `insert into public.photo`. Côté supabase-js, `ErreurBase.code === "plafond"`.

- [ ] **Étape 1 : écrire le test.** Mise en place comme `autorisations_test.sql` : un Créateur, un livre par `creer_projet`, rôle `authenticated`. Insérer 100 photos d'un coup (`generate_series`, empreinte `lpad(to_hex(n), 64, '0')`).
  - `is(count, 100)` : `Un livre accepte 100 photos`
  - `throws_ok(insert de la 101e, 'P0001', 'plafond', …)` : `La 101e photo est refusée`
  - après `delete` d'une photo, `lives_ok(insert)` : `Supprimer une photo libère une place`
  - `throws_ok` sur un `insert` de 2 lignes dans un livre à 99 : `Un insert de plusieurs lignes ne dépasse pas le plafond`

- [ ] **Étape 2 : lancer** `supabase test db`. Attendu : les refus échouent.

- [ ] **Étape 3 : écrire la migration.** Fonction `public.verifier_plafond_photos() returns trigger`, `language plpgsql`, `security definer`, `set search_path = ''`, commentée (pourquoi le verrou, pourquoi 100 : renvoi à la spec). Elle appelle `perform public.verrouiller_projet(new.projet_id)`, puis compte `public.photo` du livre et lève si le compte est `>= 100`. Trigger `verifier_plafond_photos before insert on public.photo for each row`. `revoke execute … from public, anon, authenticated`.

  `verrouiller_projet` lit `auth.uid()` : appelé depuis une fonction `security definer`, il voit toujours le jeton de la requête. Le trigger s'exécute avant la RLS `with check` : un livre d'autrui lève donc `introuvable`, pas `42501`. Le vérifier dans `autorisations_test.sql` (« Alice n'ajoute pas de photo au livre de Bob ») et adapter le code attendu si ce test existe.

- [ ] **Étape 4 : lancer** `supabase db reset && supabase test db`. Attendu : tout passe, `privileges_fonctions_test.sql` compris (la fonction trigger n'est exécutable par personne).

- [ ] **Étape 5 : régénérer les types** `supabase gen types typescript --local > packages/shared/src/base.ts`. Attendu : aucune différence (une fonction trigger n'apparaît pas). S'il y en a une, la commiter avec la migration.

### Tâche 4 : l'import respecte le plafond

**Interfaces :**
- Consomme : `ErreurBase.code === "plafond"` (tâche 3).
- Produit :
  - `export const PHOTOS_PAR_LIVRE_MAX = 100;` dans `entrees.ts`, avec un commentaire qui dit que la base fait foi (`verifier_plafond_photos`).
  - `export class ErreurPlafond extends Error` dans `importer.ts`, à côté d'`ErreurDoublon`.
  - `Echec["raison"]` gagne `"plafond"`.

- [ ] **Étape 1 : écrire les tests** dans `importer.test.ts`, avec `PHOTOS_PAR_LIVRE_MAX` importé de `@bookopia/shared` :
  - `n'importe que les places restantes` : `lireEmpreintes` rend 98 empreintes, 5 fichiers nouveaux. Attendu : `importees === 2`, 3 échecs `{ raison: "plafond" }`, `preparer` appelé 2 fois.
  - `les doublons ne prennent pas de place` : 99 empreintes, sélection de 2 doublons et 1 nouveau. Attendu : `doublons === 2`, `importees === 1`, aucun échec.
  - `un livre plein ne prépare rien` : 100 empreintes, 3 fichiers nouveaux. Attendu : 3 échecs `plafond`, `preparer` jamais appelé.
  - `le refus de la base compte comme plafond` : `envoyer` lève `new ErreurPlafond()`. Attendu : 1 échec `plafond`, l'import continue avec les fichiers suivants.
  - `un échec d'envoi rend sa place` : 99 empreintes, le premier envoi lève une erreur quelconque, le second réussit. Attendu : `importees === 1`, 1 échec `envoi`.

- [ ] **Étape 2 : lancer** `npm test -w apps/web -- importer`. Attendu : les cinq nouveaux tests échouent.

- [ ] **Étape 3 : implémenter.**
  - `importer.ts` : `let places = PHOTOS_PAR_LIVRE_MAX - empreintes.size;` après la lecture des empreintes. Juste après `empreintes.add(empreinte)`, si `places <= 0`, échec `plafond` et `return` ; sinon `places -= 1`. Tout échec qui suit (préparation, envoi, `ErreurPlafond` mise à part) rend la place (`places += 1`). `ErreurPlafond` donne la raison `plafond`. Le calcul est sans `await` entre lecture et décrément : les trois ouvriers ne peuvent pas réserver la même place.
  - `envoyer.ts` : dans le `catch`, après la suppression des fichiers, `if (erreur instanceof ErreurBase && erreur.code === "plafond") throw new ErreurPlafond();`.
  - `ImportPhotos.tsx` : `plafond: "Livre complet (100 photos)"`.
